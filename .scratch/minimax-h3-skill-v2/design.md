# MiniMax H3 Skill v2 设计说明

## 1. 目标

在保留当前 skill 中文需求编排能力的基础上，整合 MiniMax 官方 `h3-prompt-writing` 的模式、字段、引用标签、时间、对白和音频规则，并通过可扩展风格路由支持官方首批八种风格。

交付物是一个可读、可维护、可回归检查的提示词 skill；不调用 MiniMax API，不上传或验证媒体文件，不生成视频文件。

## 2. 非目标

- 不在通用核心中实现具体视频生成或剪辑执行。
- 不把八种风格的全部生产流程复制进通用 skill。
- 不自动读取参考媒体并声称已完成文件级校验。
- 不虚构用户没有提供的品牌事实、台词、Logo、字幕或产品卖点。
- 不为未来风格预先创建大量空模板。

## 3. 分层架构

```text
用户请求
  -> 输入模式识别
  -> 素材与引用建模
  -> 风格路由（可选）
  -> H3 结构化编排
  -> 质量检查
  -> 用户可读说明 + 可复制 H3 prompt
```

### 3.1 通用核心

负责模式、素材、时间线、Shot、镜头、对白、声音、保持项、禁止项和 H3 字段顺序。

### 3.2 风格路由

只负责识别明确的风格/任务意图，注入风格约束，并在不匹配时退回通用模式。

### 3.3 风格配置

每种风格定义适用任务、不适用任务、媒介、默认镜头语言、声音策略、生产阶段和专属检查项。新增风格不得改变基础模式协议。

## 4. 模式模型

### 4.1 基础模式

| 模式 | 触发条件 | 核心规则 |
|---|---|---|
| T2VA | 无参考素材的纯文生 | 从文本构造完整视听时间线 |
| I2VA | 用户明确指定首帧 | 从 0.00 秒首帧向后连续发展 |
| FL2VA | 用户明确指定首帧和尾帧 | 描述第一帧到最后一帧的连续路径 |
| L2VA | 用户明确指定尾帧但没有首帧 | 从合理前置状态逐步收敛到最后一帧 |

单张图片默认不是 I2VA；两张图片默认不是 FL2VA，除非用户明确指定关键帧角色。

### 4.2 全参考和编辑关系

| 关系 | 触发条件 |
|---|---|
| Ref2VA | 多素材提供人物、场景、动作、运镜、风格或音频参考 |
| Video Editing | 原视频被直接修改 |
| Video Continuation | 从原视频结尾继续、延长或衔接 |
| Audio Reuse | 直接复制全部或部分原音频信号 |
| Audio Reference | 只参考音色、节奏、歌词、情绪或声音质感 |

这些关系可以组合，例如 `[video editing + audio reuse]`。

## 5. 素材模型

用户层继续使用：

```text
@图片1、@视频1、@音频1
```

内部/最终 prompt 使用官方标签：

```text
<Subject N>  可复用的内容对象，如人物、产品、场景
<Picture N>  具体图片关键帧或构图锚点
<Video N>    视频来源、编辑对象、镜头/节奏结构
<Audio N>    独立音频或明确启用的音频轨道
```

必须区分：

1. 来源文件是什么；
2. 从文件中提取什么内容；
3. 内容在目标视频中锁定、迁移或仅参考什么维度。

引用关系使用：

```text
fully_preserved
partially_preserved
attribute_transfer
weak_reference
```

音频关系使用：

```text
fully_copy
partially_copy
reference
weak_reference
```

## 6. 输出协议

### 6.1 用户可读层

保持当前输出顺序：

```text
模式判断
素材映射
可直接复制的 H3 提示词
必要提醒
```

### 6.2 基础模式 prompt

默认使用官方字段和顺序：

```text
[关键帧对齐指令（仅 I2VA/FL2VA/L2VA）]

integrated_multimodal_description: ...

overall_soundscape: ...

non_diegetic_music: ...
```

字段职责：

- `integrated_multimodal_description`：画面、动作、景别、镜头、对白、演唱和画内声音。
- `overall_soundscape`：全片环境声、动作声和非语言人声；不重复对白和歌曲。
- `non_diegetic_music`：角色听不到、仅观众听到的背景音乐；无音乐使用 `N/A`。

### 6.3 Ref2VA prompt

固定六段：

```text
subject_definitions
summary
retention_analysis
detailed_description
overall_soundscape
non_diegetic_music
```

所有引用标签在六段中保持含义和编号稳定。

## 7. 时间、镜头和对白

- 第一镜使用 `[Shot 1]`，不强制添加切镜时间。
- 后续镜头使用严格递增的 `MM:SS.mmm` 切镜时间。
- 关键帧对齐时间固定为两位小数，例如 `0.00`、`8.00`。
- 镜头运动优先表达为运动类型 + 有意义的幅度 + 有意义的速度。
- 复杂内容按 Shot 拆分；单一连续动作优先使用一镜到底时间线。
- 说话人使用稳定 `(S1)`、`(S2)`，跨镜不得重新编号。
- 对白和歌词原文写入 `<d>[Language] ...</d>`。
- 跨镜连续对白使用 `<scenetrans>` 及明确的声音连续说明。
- 视频结尾截断的对白使用 `<cutoff>`。
- 画外音必须明确说话人和画面人物嘴唇保持闭合。
- 画面可见文字用英文双引号包裹，保留原文和标点，不自动翻译。

## 8. 声音策略

区分三类声音：

1. **画内/叙事声音**：对白、歌唱、现场广播、电视、手机播放等，写入主画面时间线。
2. **整体环境声**：环境、动作、呼吸、碰撞等，写入 `overall_soundscape`。
3. **非叙事背景音乐**：角色听不到的配乐，写入 `non_diegetic_music`。

用户未指定音乐时不主动添加 BGM；用户明确不要音乐时使用 `N/A` 并说明不添加额外背景音乐。

## 9. 风格路由

首版只路由官方当前八种风格：

1. 极简产品广告
2. 3D 动画短片
3. 纸艺定格解释
4. 品牌宣传片
5. 音乐视频字幕
6. 双人合作游戏开场
7. 纸张拼贴解释
8. 手绘实拍混合

路由原则：

- 只有用户明确风格或任务意图时才启用。
- 风格路由不得覆盖用户明确的主体、台词、素材用途和修改项。
- 风格配置只增加约束，不改变 H3 模式和字段协议。
- 风格不匹配或信息不足时，退回通用模式并说明必要假设。
- 后续新增风格遵循相同配置结构，不修改核心流程。

每种风格配置包含：

```text
名称
适用任务
不适用任务
默认媒介/视觉语言
常用镜头与节奏
角色/场景一致性要求
声音默认策略
文字/字幕策略
是否需要分镜或阶段确认
风格专属验收项
```

## 10. 兼容策略

- 用户解释、模式判断和素材映射默认使用用户语言。
- 最终 H3 prompt 默认使用官方英文结构。
- 对白、歌词、字幕、Logo、按钮和 UI 文案保留用户原文。
- 保留当前中文五段概念作为展示层，不保留与官方协议冲突的旧内部语义。
- 超限不静默丢弃素材；提示词过长只压缩重复修饰，不删除核心事实、时间线、文字和禁止项。

## 11. 验收重点

必须覆盖：T2VA、I2VA、FL2VA、L2VA、Ref2VA、视频编辑、视频续接、音频复用、音频参考、八种风格路由，以及素材冲突、台词跨镜、屏幕文字、超限和多语言文案。
